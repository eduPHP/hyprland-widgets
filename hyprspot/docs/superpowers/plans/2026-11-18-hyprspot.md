# hyprspot — plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Mini player de Spotify para Hyprland, sempre por cima, com modo compacto e modo expandido (playlists e busca), tocando pelo Spotify Soloist.

**Architecture:** Um processo Python (`Gtk.Application` de instância única) desenha uma layer surface GTK4 na camada OVERLAY. O estado vem do WebSocket local do Soloist, por push; os comandos de player vão pelo mesmo WebSocket, com atualização otimista. A Web API (PKCE) serve só para listar playlists, buscar e ler Curtidas. A lógica pura (parsers, reducer, CLI, cache, expiração) é testada com pytest; a UI é verificada manualmente com checklist.

**Tech Stack:** Python 3.14, PyGObject, GTK 4.22, Gtk4LayerShell 1.0, libsoup 3 (HTTP e WebSocket), stdlib (`tomllib`, `json`, `hashlib`). Sem dependências do pip. Testes: pytest 9.

**Spec:** `docs/specs/2026-11-18-hyprspot-design.md`, com a §15 sobrepondo §7 e §9 onde divergem (Soloist em vez de spotifyd, WebSocket em vez de MPRIS e polling).

## Global Constraints

- Sem pacotes do pip. Só stdlib + PyGObject (`Gtk 4.0`, `Gdk 4.0`, `Gio`, `GLib`, `Soup 3.0`, `Gtk4LayerShell 1.0`).
- Wrapper `bin/hyprspot` exporta `LD_PRELOAD=/usr/lib/x86_64-linux-gnu/libgtk4-layer-shell.so.0` antes de `python3 -m hyprspot`.
- Layer surface: namespace `hyprspot`, camada `OVERLAY`, `exclusive_zone = 0`, âncora padrão `bottom-right`, margem `16, 16`.
- Compacto **320×64** (raio 14); expandido **360×520** (raio 16, borda 1 px `#7aa2f7` a 45 %).
- Cores: fundo `#1a1b26` a 94 %, campo/abas `#16161e`, superfície `#24283b` / `#292e42`, texto `#c0caf5`, texto 2 `#9aa5ce`, acento `#7aa2f7`, tocando `#9ece6a`, curtida/erro `#f7768e`, placeholder `#8089b3`.
- Fontes: Inter (UI) e JetBrains Mono (tempos, device, dicas). Tamanhos: título 13/600 (compacto) e 14/600 (expandido), lista 13/500, artista 11.5/400, mono 10.5.
- Capas 48 (compacto), 52 (expandido), 34 (listas); botões 34; play 36/44; linha de lista 46; progresso 2 px (compacto) / 4 px (expandido).
- Soloist: WebSocket em `ws://127.0.0.1:9090`, serviço `soloist.service`, binário `~/.local/bin/soloist`, chave em `~/.config/hyprspot/soloist.env`, build expira 90 dias após a data de build (sai com código 10).
- Web API: redirect `http://127.0.0.1:8898/callback`; scopes `user-read-playback-state user-modify-playback-state user-read-currently-playing playlist-read-private playlist-read-collaborative user-library-read user-library-modify`; busca `type=track&limit=10`; token em `~/.config/hyprspot/token.json` (0600, já existe do spike).
- Config em `~/.config/hyprspot/config.toml`; cache em `~/.cache/hyprspot/` (capas LRU 50 MB em `art/`, `playlists.json`).
- Atalhos: `SUPER + ALT + M` toggle, `SUPER + ALT + S` expandir na busca, `SUPER + ALT + H` esconder/mostrar (`SUPER + SHIFT + ALT + M` já está em uso). Teclas `XF86AudioPlay/Next/Prev` livres hoje.
- Hyprland usa config Lua (Omarchy): `o.bind("TECLAS", "Descrição", "comando")` em `~/.config/hypr/bindings.lua`, `o.launch_on_start("cmd")` em `~/.config/hypr/autostart.lua`.
- Expandir/recolher: ≤ 120 ms de animação ou nenhuma; recolher 150 ms após perder o foco.
- Toda chamada de rede é assíncrona no main loop do GLib; nada bloqueia a UI.

## Review Focus

1. **Soloist fora do ar ou WebSocket caindo no meio do uso** → o widget mostra "Sem conexão com o player", desabilita os controles e reconecta sozinho (backoff 0,5 / 1 / 2 / 5 s) sem travar nem gerar exceção. Teste no Task 4 (`test_backoff_sequence`) e no Task 5 (`test_disconnect_marks_offline`).
2. **Soloist sem login** (sessão perdida) → em vez de "Nada tocando", mostra "Abra o Spotify no celular e escolha hyprspot". Teste no Task 5 (`test_auth_state_logged_out`).
3. **Token expirado, refresh recusado ou sem rede** → playlists continuam vindo do cache; a busca mostra um erro discreto; um 429 com `QUOTA_EXCEEDED` pausa as chamadas à API por 60 s. Testes no Task 6 (`test_retry_delay_*`) e no Task 3 (`test_needs_refresh`).
4. **Cliques rápidos repetidos** (next ×5, rolar volume sem parar) → volume enviado no máximo a cada 100 ms com o valor final garantido; o estado final bate com o do Soloist. Teste no Task 5 (`test_volume_throttle_keeps_last`).
5. **Títulos longos, acentos, emoji ou CJK; faixa sem capa** → elipse sem deslocar os botões; capa substituída por um placeholder. Teste no Task 4 (`test_entity_without_cover`) e verificação manual no Task 8.
